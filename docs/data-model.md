# Data Model Documentation

This document describes the data model for the LTI (Learning Tracking Initiative) application, including entity descriptions, field definitions, relationships, and an entity-relationship diagram.

# Model Descriptions

---

## AuditResult
Stores the overall result of an AI audit executed for a conversation. This entity acts as the aggregate root for all audit-related information.

**Fields:**

- `auditId`: Unique identifier for the audit (Primary Key, UUID)
- `chatId`: Identifier of the audited conversation
- `assistantId`: Identifier of the AI assistant that handled the conversation
- `status`: Current execution status of the audit
- `frustrationDetected`: Indicates whether customer frustration was detected during the conversation
- `lostLeadDetected`: Indicates whether a potential lost sales opportunity was detected
- `leadScore`: AI-generated score representing the quality of the lead
- `gapsCount`: Total number of knowledge gaps identified during the audit
- `errorMessage`: Error details when the audit execution fails
- `createdDate`: Timestamp when the audit record was created
- `auditedDate`: Timestamp when the audit process completed

**Validation Rules:**

- `auditId` is required and must be unique.
- `chatId` is required.
- `assistantId` is required.
- `status` is required and should belong to the audit status catalog.
- `frustrationDetected` must contain a boolean value.
- `lostLeadDetected` must contain a boolean value.
- `leadScore` should be between `0.000` and `1.000`.
- `gapsCount` must be greater than or equal to zero.
- `createdDate` is required.
- `auditedDate` cannot be earlier than `createdDate`.
- `errorMessage` is optional and should only contain information when the audit status is `FAILED`.

**Relationships:**

- `auditGaps`: One-to-many relationship with `AuditGap`
- `auditSentiments`: One-to-many relationship with `AuditSentiment`
- `auditRecommendations`: One-to-many relationship with `AuditRecommendation`

---

## AuditGap
Stores knowledge gaps detected during the audit process. Each record represents a customer question that the assistant was unable to answer adequately.

**Fields:**

- `gapId`: Unique identifier for the knowledge gap (Primary Key, UUID)
- `auditId`: Foreign key referencing the associated audit
- `messageId`: Identifier of the conversation message where the gap was detected
- `questionText`: Customer question identified as a knowledge gap
- `confidenceScore`: AI confidence score indicating certainty of the detected knowledge gap

**Validation Rules:**

- `gapId` is required and must be unique.
- `auditId` is required and must reference an existing `AuditResult`.
- `messageId` is required.
- `questionText` is required and cannot be empty.
- `confidenceScore` should be between `0.000` and `1.000`.

**Relationships:**

- `auditResult`: Many-to-one relationship with `AuditResult`

---

## AuditSentiment

Stores sentiment analysis results generated for each analyzed conversation message.

**Fields:**

- `sentimentId`: Unique identifier for the sentiment record (Primary Key, UUID)
- `auditId`: Foreign key referencing the associated audit
- `messageId`: Identifier of the analyzed conversation message
- `label`: Sentiment classification assigned by the AI model
- `score`: Confidence score of the sentiment prediction
- `sequenceOrder`: Sequential position of the message within the conversation

**Validation Rules:**

- `sentimentId` is required and must be unique.
- `auditId` is required and must reference an existing `AuditResult`.
- `messageId` is required.
- `label` is required and should belong to the sentiment catalog.
- `score` should be between `0.000` and `1.000`.
- `sequenceOrder` must be greater than zero.

**Relationships:**

- `auditResult`: Many-to-one relationship with `AuditResult`

---

## AuditRecommendation

Stores recommendations generated by the AI engine to improve future conversations or recover potential business opportunities.

**Fields:**

- `recommendationId`: Unique identifier for the recommendation (Primary Key, UUID)
- `auditId`: Foreign key referencing the associated audit
- `type`: Recommendation category
- `suggestedText`: AI-generated recommendation text
- `originMessageId`: Identifier of the conversation message that originated the recommendation

**Validation Rules:**

- `recommendationId` is required and must be unique.
- `auditId` is required and must reference an existing `AuditResult`.
- `type` is required and should belong to the recommendation type catalog.
- `suggestedText` is required and cannot be empty.
- `originMessageId` is optional.

**Relationships:**

- `auditResult`: Many-to-one relationship with `AuditResult`

# Contrato de mensajería — `conversation.audit.requested` (US-01)

Este contrato documenta el evento publicado en RabbitMQ para solicitar la auditoría de una conversación. Su publicación se implementa en `US-01`; el consumo y procesamiento corresponden a `US-02` en adelante.

## Topología AMQP

| Elemento | Valor | Propiedad de configuración |
|---|---|---|
| Exchange | `auditbot.exchange` (direct, durable, no auto-delete) | `auditbot.messaging.exchange` |
| Cola | `conversation.audit.queue` (durable, no exclusiva, no auto-delete) | `auditbot.messaging.queue` |
| Routing key | `conversation.audit.requested` | `auditbot.messaging.routing-key` |

La cola queda enlazada al exchange mediante la routing key anterior. Ambos recursos se declaran al iniciar el contexto de Spring mediante `RabbitAdmin`.

## Versión del contrato

`schemaVersion` debe ser exactamente `"1.0"`. Cambios incompatibles (renombrar o eliminar campos obligatorios, cambiar tipos) requieren una nueva versión de esquema y, si es necesario, una nueva routing key. Cambios aditivos y compatibles (nuevos campos opcionales) pueden mantener la versión `1.0`.

## Estructura del payload (JSON, UTF-8)

```json
{
  "eventId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "schemaVersion": "1.0",
  "occurredAt": "2026-08-31T09:00:00Z",
  "producer": "smart-chatbot",
  "conversation": {
    "chatId": "chat-123",
    "assistantId": "assistant-1",
    "startedAt": "2026-08-31T09:00:00Z",
    "endedAt": "2026-08-31T09:00:30Z",
    "messages": [
      {
        "messageId": "msg-1",
        "role": "USER",
        "content": "hola, necesito ayuda",
        "occurredAt": "2026-08-31T09:00:00Z"
      }
    ]
  }
}
```

### Tabla de campos

| Campo | Tipo | Obligatorio | Descripción |
|---|---|---|---|
| `eventId` | UUID | Sí | Identificador único del evento. Se usa como `messageId` AMQP y como correlación del publisher confirm. |
| `schemaVersion` | string | Sí | Debe ser exactamente `"1.0"`. |
| `occurredAt` | Instant (ISO-8601 UTC) | Sí | Instante lógico de creación del evento. |
| `producer` | string | Sí | Identificador del sistema productor (por ejemplo, `smart-chatbot`). |
| `conversation.chatId` | string | Sí | Identificador de la conversación auditada. |
| `conversation.assistantId` | string | Sí | Identificador del asistente de IA que participó en la conversación. |
| `conversation.startedAt` | Instant (ISO-8601 UTC) | Sí | Instante de inicio de la conversación. |
| `conversation.endedAt` | Instant (ISO-8601 UTC) | No | Instante de fin de la conversación, si ya finalizó. Debe ser mayor o igual a `startedAt`. |
| `conversation.messages` | array | Sí (no vacío) | Lista de mensajes ordenados ascendentemente por `occurredAt`. |
| `messages[].messageId` | string | Sí | Identificador único del mensaje dentro de la conversación. |
| `messages[].role` | string | Sí | Uno de `USER`, `ASSISTANT`, `SYSTEM`. |
| `messages[].content` | string | Sí | Contenido textual del mensaje. |
| `messages[].occurredAt` | Instant (ISO-8601 UTC) | Sí | Instante en que ocurrió el mensaje. |

## Propiedades AMQP del mensaje

| Propiedad | Valor |
|---|---|
| `contentType` | `application/json` |
| `contentEncoding` | `UTF-8` |
| `deliveryMode` | `2` (persistente) |
| `messageId` | `eventId` |
| `timestamp` | Instante de publicación (reloj UTC del servicio) |
| Header `schemaVersion` | Igual al campo `schemaVersion` del payload |
| Header `producer` | Igual al campo `producer` del payload |

## Semántica de entrega

La publicación usa publisher confirms correlacionados (`spring.rabbitmq.publisher-confirm-type=correlated`) junto con publisher returns (`spring.rabbitmq.publisher-returns=true`) y envío `mandatory` (`spring.rabbitmq.template.mandatory=true`). El productor considera exitosa la publicación solo cuando recibe un confirm positivo y el mensaje no fue devuelto como no enrutable.

La entrega es **at-least-once**: un mismo `eventId` puede llegar más de una vez si el llamador reintenta tras un fallo de red o timeout. No hay reintento automático oculto por parte de este servicio; el llamador decide su propia política de reintento. La idempotencia de consumo (evitar procesar dos veces el mismo `chatId`/`eventId`) queda fuera del alcance de `US-01` y será resuelta por `US-02`.

## Configuración

### `auditbot.messaging.*` (`application.properties`)

| Propiedad | Default | Descripción |
|---|---|---|
| `auditbot.messaging.exchange` | `auditbot.exchange` | Nombre del exchange direct. |
| `auditbot.messaging.routing-key` | `conversation.audit.requested` | Routing key usada para publicar y enlazar la cola. |
| `auditbot.messaging.queue` | `conversation.audit.queue` | Nombre de la cola durable. |
| `auditbot.messaging.confirm-timeout` | `5s` | Tiempo máximo de espera del publisher confirm. |
| `auditbot.messaging.max-payload-size` | `1MB` | Tamaño máximo del JSON serializado antes de publicar. |

### Conexión al broker (`spring.rabbitmq.*`)

El host, puerto, usuario, contraseña y TLS se obtienen de las propiedades estándar de Spring Boot, resueltas a variables de entorno en `application-prod.properties`:

| Propiedad | Variable de entorno | Default |
|---|---|---|
| `spring.rabbitmq.host` | `RABBITMQ_HOST` | — (requerido) |
| `spring.rabbitmq.port` | `RABBITMQ_PORT` | `5672` |
| `spring.rabbitmq.username` | `RABBITMQ_USERNAME` | — (requerido) |
| `spring.rabbitmq.password` | `RABBITMQ_PASSWORD` | — (requerido) |
| `spring.rabbitmq.ssl.enabled` | `RABBITMQ_SSL_ENABLED` | `false` |

Ningún valor real de host, usuario, contraseña o certificado se versiona en el repositorio.

## Fuera de alcance de este contrato

- Consumo del mensaje, validación previa a DLQ e idempotencia de consumo (`US-02`).
- Ejecución de analyzers de IA y persistencia de resultados de auditoría.
- Cifrado de campos dentro del payload.
